# 0.1.9 provider, session and host-runtime checks

Offline rows run on a new copy of the migrated result
([reuse the result](migration.md#reuse-the-result)) inside the verified
[containment](README.md#containment) boundary, from the
[CLI shell](README.md#cli-shell). A copied session acts through
[`as_session`](README.md#copied-session-tokens); an admin acts through
`tb ... --as-user "$test_admin"`:

```sh
test_admin="$(sqlite3 -readonly "${AREA_BASE:?}/state.db" "SELECT userId FROM users WHERE isAdmin = 1 ORDER BY userId LIMIT 1")"
```

The area base starts with no identity tree, homes or credentials; the gateway
seeds the shipped identity at boot. Never copy provider credentials from the
source database or any live base.

Online rows run on a fresh empty base under the [online tier](README.md#tiers)
and are labelled "fresh-base feature evidence, not proof on migrated state".
The feature smoke's `provider` area ([feature smoke](README.md#feature-smoke),
online only) covers the local deployment projection, the identity surface and
the onboarding lifecycle. Rows marked optional need an operator-authorized
test account; without one, record them `skipped` with the missing
prerequisite. Never use a dummy or copied credential to fill that gap.

Stop isolation and the gateway shim are in
[gateway-surface.md](gateway-surface.md). Retirement cleanup is in
[artifacts.md](artifacts.md#retirement-cleanup).

| <a id="identity-current"></a>`identity current` | Offline | In a new scratch directory, write a test marker `.tightbeam-session` holding `{"sessionKey":"<copied session key>","token":"runbook-not-a-token"}`. With `TIGHTBEAM_URL` and `TIGHTBEAM_TOKEN` unset, run `"$PKG/bin/tightbeam" identity current` from that directory and from a subdirectory. Replace the marker with `{}` and run it again. | Both runs print `{"sessionKey": "<copied session key>"}` and nothing else; `runbook-not-a-token` appears nowhere in the output. The `{}` marker is refused `missing sessionKey` without echoing the file. |
| Identity status and apply | Offline | Run `tb identity status --as-user "$test_admin"`. Pick one copied active session and run `tb identity apply <session> --as-user "$test_admin"`, then read status again. Run `identity apply` on a copied retired session. | Status returns `live_revision` and `sessions[]` with `identity_revision`, `expected_identity_revision`, `identity_stale` and `identity_stale_reasons`. Apply returns `applied` naming the session and `identity_revision` equal to `live_revision`, and the second status shows that session with `identity_stale: false`. The retired session is refused `not_found`. If the session's host is unreachable inside containment, record the apply half `INCOMPLETE`. |
| <a id="guidance-presence"></a>Guidance presence | Offline | Run `tb learn agentic-engineering --as-user "$test_admin"`, then `tb identity status coder --as-user "$test_admin"`, and search the returned `guidance` text for each harness. After the apply in the row above, list that session's home under `$AREA_BASE/homes`. | The composed guidance contains `Never wait inside a turn` (#131), `spawn a helper there under your assignment` (#134), `## Prompts state the goal, not the route` (#165), and `## Test only the version under test` (#163). It also contains `## Waiting on PR checks` (#163, from the included landing guidance), and does not contain `incredibly detrimental failure mode` or `post-MVP sanity check` (#35). The applied home holds a `tightbeam-operating-manual` skill (#122). |
| <a id="session-connect"></a>Session connection | Accept offline; reply online | Run `as_session <A> session-connect --session <A>` with stdin held open. After `ready`, send one line `{"type":"send","protocolVersion":1,"requestId":"rb-1","content":"reply with SMOKE OK","idempotencyKey":"rb-connect-1"}`, then the same `requestId` again, then `not json`, then close stdin. Online, repeat on a fresh-base session and wait for its reply. | The client prints `snapshot.begin`, `snapshot.item` lines and `snapshot.end`, then `ready`. The send returns `send.accepted` with `requestId` `rb-1` and a `wakeId`, and a turn for session A carries that wake ID. The repeated request is an `input.error` `duplicate_request_id`, and the bad line an `input.error` `invalid_json`. EOF ends the client with exit 0. Online, the reply arrives as an `event` line. |
| <a id="harness-capability"></a>Harness control capability | Offline | Run `tb list --as-user "$test_admin"` and read `capabilities.setHarness` for three copied sessions on different harnesses. | Each session reports `supported` and `options[]`. The session's own harness is listed with `enabled: false`. A session that cannot change harness shows `supported: false` with a reason. |
| <a id="tune-turn-in-progress"></a>Harness change refused during a turn | Online | Run `tb tune --session <s> --harness codex` without `--model`. Start a long harmless turn on a test session, queue one more prompt to it, and run `tune --session <s> --harness <other> --model <catalog model>` while the turn runs. After it ends, run the same command, then repeat it. | The form without `--model` is a CLI usage error. During the turn the change is refused `turn_in_progress` and the queued prompt stays queued. After the turn the change is accepted, and the queued prompt is still delivered in order. The repeat names the now-resident harness and is refused `same_harness`. |
| <a id="sentinel-lifecycle"></a>Sentinel lifecycle | Offline | Before learning, run `tb sentinel list` and `tb sentinel enable agentic-engineering/landing-watch --as-user "$test_admin"`. Learn `agentic-engineering`, then run `tb kungfu setup agentic-engineering` and `tb sentinel list`. Try `sentinel enable agentic-engineering/landing-watch`. Set one setting with `host-env-set --sentinel agentic-engineering/landing-watch GH_CONFIG_DIR=/runbook/not-a-dir`, read `host-env-list --sentinel agentic-engineering/landing-watch`, and unset it. Try `host-env-set --host <another host name> --sentinel agentic-engineering/landing-watch GH_CONFIG_DIR=x`. | Before learning, enable is refused `kungfu_not_learned` or `unknown_sentinel`. After learning, `sentinel list` shows `landing-watch` with `requires`, `missing` naming `GH_CONFIG_DIR` and `LANDING_REPOS`, and state `disabled`. Enable is refused `sentinel_settings_missing`. The listed setting shows its name, never `/runbook/not-a-dir`, and the unset removes it. The other host is refused `sentinel_host_not_local`. Enabling for real is in the online [landing watcher](work-routing.md#landing-watcher) row. |
