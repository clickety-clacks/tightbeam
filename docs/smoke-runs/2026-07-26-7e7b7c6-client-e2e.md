## Deviations / findings

- **SUBSTRATE DEFECT (codex, steps 14 and 15): a turn crashes after a gateway
  restart.** `Tightbeam.Gateway.harness_session/6` asks the adapter process
  `knows_session?` — the lazy re-adoption authority — through a
  `GenServer.call` with the DEFAULT 5s timeout. A freshly booted codex adapter
  is still in its own boot (which includes the gate wiring-check probe) and
  does not service the call in time, so the call times out, the turn Task dies,
  and the row is published `failed (:task_crash)`. Captured stacktrace, from
  the leg's own gateway log:

  ```
  ** (stop) exited in: GenServer.call(#PID<0.246.0>, {:knows_session?, "019f9cc4-…"}, 5000)
      ** (EXIT) time out
      (tightbeam) lib/tightbeam/gateway.ex:1425: Tightbeam.Gateway.harness_session/6
      (tightbeam) lib/tightbeam/gateway.ex:1069: anonymous fn/3 in Tightbeam.Gateway.turn_runner/1
  ```

  Reproduced twice (full matrix run and an isolated codex J7 probe). The claude
  leg passes the same steps — its adapter answers inside the window — so this
  is a cold-adapter race, not a restart-semantics failure per se. NOT fixed
  here: this lane owns the driver, and changing turn/adapter behaviour needs its
  own authority. Related but distinct from tasks #16 and #19.
- **P-codex is INCOMPLETE by design, not by accident.** The driver measures
  whether a harness's catalog fetch is credential-gated (fetch from a copy of
  the org with the credential store removed). Claude's is gated, so its
  successful fetch proves a live grant. Codex's is cache-backed, so it proves a
  file exists — an expired credential beside a populated cache would look
  identical. That is presence-only and is recorded as INCOMPLETE naming task
  #15, rather than a PASS nobody should trust.
