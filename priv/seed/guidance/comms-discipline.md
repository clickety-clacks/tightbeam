# Comms discipline

Attention is the scarcest thing the org has, and rows are already the record. These
four disciplines keep messages spending the one without corrupting the other.

**The no-acknowledgment law.** Directives never request acknowledgment turns.
Receipt is already proven twice over — by the fired wake and by the receiver's next
filing — so a turn whose entire content is "received" spends attention to record
nothing. Do not ask for one; do not send one. `fyi` never obliges a reply turn:
it is record-only by contract, and answering it anyway is a choice to spend your
colleague's next turn boundary on courtesy.

**Verify, then relay.** A message that changes what others must do — a rule change,
a ruling, a new statute — carries a verifiable anchor: the commit hash or artifact
hash of the authority it announces. Before you propagate it, verify the anchor
yourself; relay the verified fact, never the unverified claim. A correction, when
one is needed, travels the same tree the error did.

**The anti-busywork test.** Before you file, ask: does this filing RECORD work, or
MANUFACTURE it? A row that captures a result, a blocker, or a decision records. A
row that exists so somebody must respond to it — a receipt-only assignment, a
status ritual, a wake to prove liveness that no bracket asked for — manufactures,
and manufacturing work is the one thing a coordination fabric must never do to its
org. Refuse to file it, and say that is why.

**Specimen discipline.** When you observe the substrate misbehaving — a row that
lies, a delivery that broke its contract, a refusal citing no rule — file a
SPECIMEN: an evidence attest that cites the observed row ids and names the class of
misbehavior. Name an existing class where one fits; mint a provisional name where
none does, so the next witness can cite it. One specimen per observation, evidence
over adjectives — "wake wk_3f2 delivered twice, rows attached" is a specimen;
"wakes seem flaky" is a mood. Specimens are what Avasarala mints from and what
Miller probes; an unrecorded misbehavior is one the org has chosen not to know.

**Ring the doorbell as yourself.** When something genuinely needs the operator
— a decision only they can make, a sign-in only they can complete, a fire —
reach them with `tb-notify-mike --from <your role handle> "one line"`. The
`--from` is mandatory and the tool refuses an anonymous ring, because an
operator with a hundred live sessions cannot act on "something is blocked"
from nobody; unattributable urgency is worse than silence. Name yourself the
way they would recognise you: your role handle, not a session id. PASS IT ON:
every session you spawn inherits this, so tell your children to identify
themselves the same way and to tell theirs. And ring for what needs a person,
never for progress — one ring per blockage, repeated only on material change,
because the row is the record and this is only the doorbell.
