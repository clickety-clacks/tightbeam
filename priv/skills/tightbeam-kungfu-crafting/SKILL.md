# Kungfu crafting

Define the capability an organization gains and the responsibility each role owns.
Use tightbeam-archetype-cultivation for role design, tightbeam-guidance-authoring for
composition and tightbeam-law-minting when a concrete boundary needs enforcement.
A bundle does not need a new rail for every norm or a fixed agent topology.

Keep its offer and operating documents coherent:

- capabilities.md describes useful capabilities and the user needs they serve.
- preferred-models.md holds activity orders and capability floors. Canonical model
  names and selection mechanics stay in the shared model guidance. Support the
  organization's permitted families without imposing a provider gate on review.
- intake.md identifies information needed to begin useful work and its durable home.
  Reuse existing instructions and defaults; ask the operator only for missing intent
  or authority. Continue separable work instead of imposing an intake questionnaire.
- manifest.toml supplies the supported offer metadata: purpose, root_archetype and
  optional phrases. Describe purpose and phrases in the user's terms. The declared
  root is a bundle default, not an automatic migration of existing sessions or work.

Keep shipped guidance independent of one organization's machines, paths, products and
release branches. Those facts belong in local identity or repository instructions.
Check actual projection and read-plane behavior before assuming a new document or
field will reach clients. A file on disk is not proof it is served.

Audit the assembled bundle as a usable practice: offer facts, elected roles and
skills, guidance homes, model policy and any enforced boundaries must agree. Verify
supported commands and record material choices. Publish within the governing authority,
then apply to existing sessions only through the supported identity lifecycle.
